# MX-5 demo and the log switch (2026-11-21)

The car show is tomorrow. ivan's correction to the first plan: **do not boot
into a mode with no car behind it** — the app always takes its normal boot path
(WiFi, adapter, handshake). What has to improve is the demo that already exists,
so that it looks like his MX-5 instead of the MiTo it imitated, and the demo has
to be what a boot with no adapter lands on instead of an empty dashboard. The
log switch stays: it is the other half of the request.

## What is asked

1. "Don't boot directly into nothing": with no adapter found, the dashboard
   must not sit on `N/D`.
2. "Just improve the demo mode to make it MX5 mode": the existing demo (hold
   `L`+`R`) has to read as his car — MAF, naturally aspirated, six speeds, water
   at MX-5 temperatures.
3. "Remove the writing log on file": stop the log file being written when it is
   not wanted.

## Constraints

- **The driving path is not touched.** No branch is added to the adapter, WiFi,
  handshake or scheduler path. `log=2` is today's behaviour and the demo only
  runs by the chord or by the explicit no-adapter fallback.
- **The demo data is the existing generator**, not a second one: `demo_update()`
  keeps writing into `g_store` with `OBD_SRC_SIMULATED`, and the `DEMO` chip in
  the header keeps saying so.
- **Never simulated data where the car's belongs**: the fallback only fires when
  there is no socket at all, never on a link that answered; any later successful
  connection turns it off before a single request goes out.
- Read-only toward the car, as always: no new service, no new request.
- No deletions on the Memory Stick, and the EBOOT is replaced only after a
  review and a hash check.

## 1. The demo becomes an MX-5 NB2

`demo_apply_flags(1)` (what the chord and the fallback call):

| | before (MiTo) | now (MX-5 NB2) |
|---|---|---|
| airflow | MAP, no MAF | MAF present (`0x10`), MAP kept so boost and the oil estimate have a source |
| throttle | `0x49`, label `ACELERADOR` | `0x11`, label `MARIPOSA` |
| trims and advance | MiTo encoding | standard encoding |

`demo_update()`:

- **Engine speed from road speed and the car's own gear table**:
  `rpm = 1000 × km/h / gear_kmh[gear]`, taking `gear_kmh` from the
  `MAZDA_MX5_NB2` profile in `src/core/vehicle.c` — the same table the app
  already uses to work out the gear, anchored to the real car ("3,000 rpm in
  fifth is 101 km/h, which is what the car shows"). 101 km/h in second is 6,966
  rpm, which is where it cuts; 100 km/h in fifth is 2,974. The tacho, the
  speedometer and the `MARCHA` tile cannot disagree, because they read one
  table.
- **The demo wears that profile**: tachometer to 8,000 with the red zone at
  7,000 and the cut at 7,200, centre of the dashboard on MAF (which is what puts
  the air/oil/water block and the gear tile on his GENERAL), and the car's name.
  Leaving the demo puts the global settings back. Nothing is written to his car
  preferences.
- **A 90 s cycle with the gear written into every segment**: idle, launch in
  first to 55 km/h, the full pull in second to 101 km/h, third to 120, fifth for
  the cruise at 105-115, lift and brake, stop. The 0.6 s segments are gear
  changes: foot off, a few km/h lost while the next ratio comes in. The pull is
  at 92 % throttle, so it really reads as wide open (MAP 90-93 kPa, MAF 75-87
  g/s), not the 78 % the slope alone produced.
- **Naturally aspirated numbers**: MAP 30 kPa at closed throttle to 96 at wide
  open (the MiTo's 200 kPa would be a fault on an MX-5), water 88-92 °C, advance
  16° at full load to 36° cruising.
- **MAF from revs and load**: `1.5 + rpm × load/100 / 75`, which is 3 g/s at
  idle and ~83 at full throttle — his own log measured 89 g/s at 6,940 rpm, so
  the shape matches the real car.
- The 2 s status line gains `maf=`, so a demo session in the log can be read
  without the screen.

## 2. No adapter, no empty dashboard

`demo_if_no_adapter(sock)` runs after the boot connection attempt and after a
failed `TRIANGLE`/`SQUARE` retry: `sock < 0` and demo off → `demo_toggle()`.
The header chip says `DEMO`, the status lines say `(SIM)`, and the summary
screen says `SIM (sin coche)`.

The reverse is the important half: the retry path already calls `demo_toggle()`
when demo is on before it connects, so a real car always takes over and nothing
simulated is ever shown once a socket exists. The same is true at boot: the
fallback runs after `connect_network_and_elm()` returned -1, never before.

## 3. The log switch

`log_full` (0/1) becomes `log` (0/1/2):

| value | writes |
|---|---|
| 0 | nothing: no file is opened |
| 1 | boot lines, the 2 s status line, connection events and the final summary — no per-command lines |
| 2 | also one line per command with its timing and the parsed reply of each (today's `log_full=1`, the default) |

- Migration: `log_full=1` reads as `log=2`, `log_full=0` as `log=1`, so the card
  as it is keeps today's behaviour.
- `log_open()` returns before `log_pick_path()` when `log<=0`: no file, and no
  `SIN LOG` warning either, because switching it off was deliberate.
- `settings_load()` moves before `log_open()`, since the LOG value decides
  whether a file is opened at all. The lines the loader used to write directly
  (truncated file, telemetry-series migration, and the `Ajustes: tema=…` summary
  that heads every log) are buffered and flushed by `settings_log_summary()`
  right after the banner, so no session loses them.

## Risks

| risk | cover |
|---|---|
| the demo shows simulated data while he believes it is the car's | the fallback needs `sock < 0` (no ELM327 answered at all); the `DEMO` chip, `(SIM)` in the log and `SIM (sin coche)` on the summary; a successful connect turns it off before any request |
| the demo values contradict each other on screen | rpm, speed and gear come from one formula; the gear tile is derived from the same pair |
| the driving path changes with today's settings | no branch added to the adapter path; `log=2` is the old `log_full=1` |
| the settings file changes shape | `log=` written, `log_full=` still read |
| a save during the day rewrites the theme | no rotation exists any more; the theme is only what he picks |

## Open points for ivan

- The cycle is 90 s with the pull in second. If he wants a longer stint (a
  lap-like loop, several pulls), it is a table change.
- `LOG` defaults to `COMPLETO`, as today. `SESION` is there for a long trip
  where he wants the summary and the timings but not a file per command.

## Review outcome (2026-11-21)

GLM 5.3 high and DeepSeek v4.1 flash high both read the plan and the diff and
both said FIX-FIRST. What they found and what changed:

| found | fix |
|---|---|
| the demo invented a six-speed gearbox while the repo's measured `MAZDA_MX5_NB2` profile is a five-speed; every gear disagreed, and the `MARCHA` tile would have read N/D or the wrong gear (both reviewers, the blocker) | the demo takes its ratios from the profile, so the two can never disagree; the cycle was retuned to 55 / 101 / 120 km/h |
| the demo never applied the car profile, so the dashboard showed BOOST and MAP on a naturally aspirated car, no gear, and the MiTo's redline (DeepSeek) | `demo_apply_car()` applies tacho, red zone, cut, MAF centre, name and layout on entry and restores the global view on exit |
| a single failed boot connection would have left the whole drive simulated, with the retry loop disabled (DeepSeek, blocker) | not fixed as proposed: a background connect would stall the demo (15 s WiFi wait). Instead the SIM state is on the header chip and `TRIANGLE` retries at once, which is the gesture he already uses. Noted here so it is a decision, not an oversight |
| `SESION` still wrote a line per command and per reply, so it was not a lighter mode at all (DeepSeek) | those three sites now require `log>=2`; `SESION` is boot, 2 s status, events and summary |
| changing LOG in the menu did nothing until the next power-on (DeepSeek) | the row closes the file and reopens it (with a fresh banner) on the spot |
| the pull was at 78-81 % throttle, so MAP and MAF did not match the comment or the docs (both) | 92 % floor while accelerating |
| idle advance at 5° where an NB2 idles near 10° (DeepSeek) | 10° ± 2 |
| the log said "sin adaptador (N/D)" while the demo was feeding values (both) | says "sin adaptador, demo MX-5 (SIM)" |
| the settings-notice buffer could cut the last line (DeepSeek) | 256 bytes |
| `g_cfg.show_fps = 1;` in the defaults block was unrelated (DeepSeek) | removed |

Verified after the fixes: the emulator log shows one full cycle — idle 831 rpm
and 3.2 g/s, 45 km/h at 5,124 rpm in first, 101 km/h at 6,939 rpm in second with
MAP 93 kPa, 115 km/h at 5,592 in third, 111 km/h at 3,295 in fifth, water 88-90
°C — with `ok=0 nd=0 to=0` (nothing sent) and the demo armed by itself because
no adapter answered.
